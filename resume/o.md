## 登录并且授权生成 JWT Token的流程

1. 通过解析用户发起的 HTTP 请求
   - 是服务端内部 gin 框架来解析
   - gin 的功能大致是：
     - 服务端的 http 相关的路由（router）管理，比如 POST /login 接口定义
     - 建立 http 连接， 维持 session 会话， 并且解析 http 方法、path、header 等信息
2. 解析出用户信息，如用户名、用户密码、手机、用户邮箱，我这里用了 email
3. 对比 mysql 数据库的已经存在的用户信息进行校验，比如用户是否存在，密码是否匹配
   - 这里通过 gorm 库进行 mysql 查询功能
4. 校验成功以后，将用户信息(用户 ID， 为后续签到准备) 包装到 JWT 中，并且设置 Token 过期时间
5. 最后通过 jwt 库和内部的 secret 密钥生成一个 token
6. 然后包装成登录响应的结构返回给用户


## 日志分级

- Info
  - 一些关键核心操作信息
  - 比如用户更新、创建、删除（带上用户 ID）
- Debug
  - 比如那个用户调用了那个方法
  - 用户更新具体字段变化，用户创建的所有关键字段
  - 用户查询操作
- Warning （告警）
  - 用户登录失败
  - 用户传入了无效的非法字段
- Error
  - 用户操作错误信息
  - 服务端错误信息（数据库连接失败， 用户增删改查失败）
