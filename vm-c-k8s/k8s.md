# Kubernetes（K8s）通俗终结版笔记

## 一、K8s 是什么（一句话）

Kubernetes 是一个 **用来自动管理和运行大量服务程序的系统**。
你不用再手动启动程序、重启服务、分配机器，K8s 负责统一管理。

---

## 二、K8s 到底跑不跑程序（核心结论）

**K8s 本身不运行业务代码，只负责管理。**
真正跑你程序的是：**容器 + 服务器**。

一句话记住：

**程序在容器里跑，容器在机器上跑，K8s 在旁边管。**

---

## 三、谁在干活，谁在管理（必须搞清）

整体关系如下：

* 你写 Go / Java 程序
* 程序打包成 Docker 镜像
* Docker 容器真正运行程序
* 容器运行在 Node（服务器）上
* K8s 负责调度、管理、维护这些容器

K8s 不执行 main.go，不跑 JVM，不处理 HTTP 请求。

---

## 四、K8s 解决了什么问题

没有 K8s 时：

* 程序挂了要手动重启
* 流量大了要手动加机器
* 更新服务要停机
* 多台机器部署混乱

用了 K8s 后：

* 程序挂了自动拉起
* 可以自动扩容
* 支持不停机更新
* 统一管理所有服务

本质一句话：
**让服务自己稳定地活着。**

---

## 五、K8s 核心概念（够用版）

### 1. Cluster（集群）

多台服务器组成的整体。

### 2. Node（节点）

一台真实的服务器，用来跑容器。

### 3. Pod（最重要）

K8s 运行程序的最小单位。
一个 Pod 里可以有一个或多个容器。
实际部署时，是部署 Pod，而不是直接部署容器。

**面试要点：Pod ≠ 容器**

### 4. Container（容器）

真正运行你 Go / Java 程序的地方。

### 5. Deployment

用来管理一组 Pod。
可以指定跑几个、副本挂了自动补、支持滚动更新。

### 6. Service

给一组 Pod 提供一个稳定的访问入口。
因为 Pod 会重建、IP 会变化，Service 保证访问不变。

---

## 六、K8s 在“管理层面”具体做什么

* 决定 Pod 跑在哪台机器上
* 决定跑几个副本
* Pod 挂了自动新建
* 服务更新时新旧版本平滑切换
* 提供稳定的网络访问方式

---

## 七、K8s 基本操作（只需眼熟）

* 查看节点
  `kubectl get nodes`

* 查看 Pod
  `kubectl get pods`

* 应用配置
  `kubectl apply -f app.yaml`

* 查看服务
  `kubectl get svc`

---

## 八、YAML 是什么

K8s 不靠写代码控制，而靠 **配置文件描述你想要什么**。

例如：

```yaml
replicas: 3
```

意思是：
我要 3 个程序实例一直在跑。

---

## 九、Docker 和 K8s 的关系（必会）

* Docker：负责运行一个容器
* K8s：负责管理一堆容器

一句话总结：
**Docker 负责跑，K8s 负责管。**

---

## 十、总结

Kubernetes 是一个容器编排系统，本身不运行业务代码，而是通过容器运行时在服务器上启动和管理容器，负责调度、扩缩容、故障恢复和服务管理。
